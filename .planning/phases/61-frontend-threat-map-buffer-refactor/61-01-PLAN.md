Per 61-UI-SPEC.md §"Accessibility — prefers-reduced-motion" and WCAG 2.3.3:

```css
/* Accessibility: prefers-reduced-motion (WCAG 2.3.3) */
/* Motion-sensitive users get instant state transitions. The JS state machine still runs; only visual expression changes. */
@media (prefers-reduced-motion: reduce) {
  .map-buffer-marker--arriving {
    animation: none;
    /* Skip the expanding pulse ring entirely — arriving markers render as transparent immediately. */
    /* The 1800ms JS timer still fires and flips state to 'settled', at which point the dot appears instantly. */
    opacity: 0;
  }

  .map-buffer-marker--evicting {
    transition: none;
    opacity: 0;
    /* Instant removal. The 600ms JS timer still runs for state cleanup; only the fade is suppressed. */
  }
}
```

Implementation note on `--arriving` in reduced-motion: setting `opacity: 0` on the arriving state (instead of trying to "flatten to a settled dot" inline) is the simplest correct approach. The arriving icon's `L.divIcon` uses `iconSize: [16, 16]`, which is wider than the 6px settled dot; reducing it to opacity 0 means the marker is invisible during the 1800ms arriving window but snaps to the 6px dot the moment the hook transitions to `settled`. No visual artifact, no double-render — just a motion-free arrival.
